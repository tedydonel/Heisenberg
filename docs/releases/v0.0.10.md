# v0.0.10 — icons in email, a working Patterns tab, an assistant that remembers

A maintenance tag over [v0.0.9](https://github.com/tedydonel/Heisenberg/releases/tag/v0.0.9):
identical behaviour, with static analysis and formatting green. **Pin this one rather than
0.0.9** — the 0.0.9 tree fails CI on PHPStan and Pint, nothing more.

Everything below shipped across 0.0.9 and 0.0.10 together. See [`UPGRADING.md`](../../UPGRADING.md)
for what it means for an existing install. Nothing is breaking, but two changes are worth a
host's attention: **email `font-family` output changed and the message now links the theme's
faces** (re-record any `EmailRenderer` snapshot), and **icon PNGs are written to the media disk
under `email-icons/` with no media-library row**.

## Highlights

Icons work in email, shipping as inline `cid:` PNGs the editor rasterizes, and a theme font
finally reaches the message instead of collapsing to Arial. The Patterns tab (formerly Blocks)
actually works — everything but the wiring already existed. The AI assistant remembers your
conversation across a refresh. The icon picker paints in one request instead of ninety-seven. And
the topbar's home button is configured on its own, per role, instead of pointing wherever
`site_url` did.

## Added

- **Icons in email documents.** No mail client renders SVG, so the icon block was excluded from
  the email palette outright. Its glyph is now rasterized by the editor at 2x — with the colour
  and size the author picked — stored under a derived name so one icon is written once and reused
  by every block, document and send, and embedded inline as a `cid:` part exactly as an image
  block already is. It arrives in the body, not as a visible attachment. Rasterizing happens in
  the browser deliberately: converting SVG server-side needs Imagick with an SVG delegate, which
  is not a dependency a package can force on a host.
- **Patterns.** The Blocks tab is now **Patterns**, and saving one works: select a group or
  column, use "Save as pattern" on its toolbar, and it comes back ready to drop in.
- **A dashboard link of its own.** `heisenberg.dashboard_url` takes a single URL, or a map keyed
  by your own role names, so an admin and staff each return to their own dashboard from the
  topbar's home button.

## Changed

- **A theme font reaches the email it is used in.** Stacks lead with the real family, the message
  links the theme's faces (Apple Mail and iOS Mail render them; Gmail and Outlook fall back
  exactly as before), and the fallback comes from the font's own catalog category rather than
  keyword-matching the token's name — a token called `font-serif` holding a sans family used to
  ship Georgia, which is why only the first theme font ever looked right in email.
- **Text with no font of its own follows the theme**, through a derived `--hb-t-font-base`.
- **The icon picker paints from one request instead of one per icon**: 97 requests and ~37s became
  1 and ~0.9s against the dev server.
- **Three theme presets instead of six**, and saving under your own name detaches from them.
- **The AI uses the theme's fonts**, and is no longer taught attributes it cannot set.

## Fixed

- **The AI forgot the conversation on refresh.** A thread started by chatting was never recorded —
  only one reopened from history was — so a reload restored nothing and the next message carried
  no prior turns.
- **Editing a duplicated block changed a different one.** A loaded document never advanced the
  block-id counter past its stored ids, so the next duplicate, insert or pattern reused an id
  already on the page.
- **An icon ignored its Fill colour**, and resizing it in one dimension did nothing visible.
- **Inserting a saved pattern could make a document unsaveable** ("expected type string").
- **Saved-pattern cards lost their shape** whenever the list refreshed.
- **A title set by the AI still showed "Untitled post"**; theme colours showed blank swatches; a
  font or size bound to a token showed its raw `var(--hb-t-…)` text.
- **Email output is byte-identical across platforms.** The shell heredoc took CRLF from a Windows
  checkout, which inflated the `sizeBytes` behind the Gmail clipping warning by ~3%.
- **A host whose `getRoleNames()` returns a plain array no longer fatals.**

## Checks

1,905 tests / 8,130 assertions pass; PHPStan reports no errors; Pint is clean.
